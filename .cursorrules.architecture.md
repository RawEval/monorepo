# Architecture-Specific Rules

## 🏗️ Feature-Based Architecture

### App Structure Pattern

Every app should follow this structure:

```
apps/[app-name]/
├── app/                    # Next.js App Router
│   ├── (public)/          # Public routes (no auth)
│   │   ├── login/
│   │   ├── signup/
│   │   └── layout.tsx
│   ├── (tenant)/          # Tenant-scoped routes (auth required)
│   │   ├── [workspaceSlug]/
│   │   │   ├── layout.tsx
│   │   │   ├── page.tsx
│   │   │   ├── chat/
│   │   │   ├── settings/
│   │   │   └── billing/
│   ├── api/               # API routes
│   │   ├── auth/
│   │   ├── webhooks/
│   │   └── trpc/
│   ├── layout.tsx
│   └── middleware.ts
│
├── features/               # Feature modules
│   ├── [feature-name]/
│   │   ├── components/    # Feature-specific components
│   │   ├── hooks/         # Feature-specific hooks
│   │   ├── services.ts    # Feature business logic
│   │   ├── types.ts       # Feature types
│   │   └── schema.ts     # Validation schemas (Zod)
│
├── components/
│   ├── ui/                # Re-export shadcn
│   ├── shared/            # Cross-feature components
│   ├── layout/            # Layout components
│   └── providers/         # Context providers
│
├── services/              # Business logic layer
│   ├── [feature]-service.ts
│   └── ...
│
├── hooks/                 # Shared hooks
├── lib/                   # App-specific utilities
└── middleware.ts          # Auth & routing middleware
```

### Feature Organization Rules

**✅ CORRECT:**
```
features/chat/
├── components/
│   ├── chat-message.tsx
│   └── chat-input.tsx
├── hooks/
│   └── use-chat.ts
├── services.ts
└── types.ts
```

**❌ WRONG:**
```
components/chat/           # Don't organize by layer
hooks/use-chat.ts         # Don't put feature hooks in root
services/chat-service.ts  # Can be here OR in features/chat/
```

### Services Layer

**Location:**
- Option 1: `services/[feature]-service.ts` (shared across features)
- Option 2: `features/[feature]/services.ts` (feature-specific)

**Rules:**
- ✅ Business logic in services, not components
- ✅ Services are async and return typed data
- ✅ Services use `@raweval/db` for database access
- ✅ Services use `@raweval/auth` for permission checks
- ❌ Don't put API calls directly in components
- ❌ Don't put business logic in hooks

**Example:**
```typescript
// services/chat-service.ts
import { db } from '@raweval/db';
import { requireSession } from '@raweval/auth';
import type { ChatMessage } from '@/features/chat/types';

export class ChatService {
  async sendMessage(sessionId: string, message: string): Promise<ChatMessage> {
    const session = await requireSession();
    // Business logic here
    return await db.chatMessage.create({ ... });
  }
}
```

### Component Organization

**Hierarchy:**
1. **`packages/ui/src/`**: Shadcn components (generated)
2. **`components/ui/`**: Re-export shadcn (app-specific)
3. **`components/shared/`**: Cross-feature (logo, empty-state, error-boundary)
4. **`components/layout/`**: Layout (header, sidebar, breadcrumbs, footer)
5. **`components/providers/`**: Context providers (auth, theme, query)
6. **`features/*/components/`**: Feature-specific components

**Rules:**
- ✅ Feature components in `features/*/components/`
- ✅ Shared components in `components/shared/`
- ✅ Layout components in `components/layout/`
- ❌ Don't create `components/[feature]/` - use `features/[feature]/components/`

### Route Groups

**Purpose:**
- Organize routes without affecting URLs
- Apply different layouts per group
- Apply middleware per group

**Structure:**
```
app/
├── (public)/          # Public routes
│   ├── login/        # /login (not /(public)/login)
│   └── signup/       # /signup
│
├── (tenant)/         # Tenant-scoped routes
│   └── [workspaceSlug]/
│       └── chat/     # /[workspaceSlug]/chat
│
└── api/              # API routes
    └── chat/         # /api/chat
```

**Layouts:**
```typescript
// app/(public)/layout.tsx
export default function PublicLayout({ children }) {
  return <div>{children}</div>; // No auth required
}

// app/(tenant)/layout.tsx
export default async function TenantLayout({ children }) {
  const session = await requireSession();
  return <WorkspaceProvider>{children}</WorkspaceProvider>;
}
```

### Middleware

**Purpose:**
- Authentication checks
- Workspace/tenant routing
- Redirects based on auth state
- Setting headers

**Location:** `apps/[app]/middleware.ts`

**Example:**
```typescript
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';
import { getSession } from '@raweval/auth';

export async function middleware(request: NextRequest) {
  const session = await getSession();
  
  // Protect tenant routes
  if (request.nextUrl.pathname.startsWith('/[workspaceSlug]')) {
    if (!session) {
      return NextResponse.redirect(new URL('/login', request.url));
    }
  }
  
  return NextResponse.next();
}

export const config = {
  matcher: ['/((?!api|_next/static|_next/image|favicon.ico).*)'],
};
```

### Multi-Tenancy

**Workspace Routing:**
```
app/(tenant)/[workspaceSlug]/
├── layout.tsx          # Workspace context provider
├── page.tsx            # Workspace dashboard
├── chat/               # Workspace chat
├── settings/           # Workspace settings
└── billing/            # Workspace billing
```

**Workspace Context:**
```typescript
// app/(tenant)/[workspaceSlug]/layout.tsx
export default async function WorkspaceLayout({
  children,
  params,
}: {
  children: React.ReactNode;
  params: { workspaceSlug: string };
}) {
  const session = await requireSession();
  const workspace = await getWorkspace(params.workspaceSlug, session.userId);
  
  return (
    <WorkspaceProvider workspace={workspace}>
      {children}
    </WorkspaceProvider>
  );
}
```

### API Routes

**Structure:**
```
app/api/
├── auth/
│   ├── route.ts        # /api/auth
│   └── callback/
│       └── route.ts    # /api/auth/callback
├── webhooks/
│   └── stripe/
│       └── route.ts    # /api/webhooks/stripe
└── trpc/
    └── route.ts        # /api/trpc
```

**Rules:**
- ✅ Use services in API routes, not direct database calls
- ✅ Validate requests with Zod schemas
- ✅ Use `@raweval/auth` for auth checks
- ✅ Return typed responses using `@raweval/types`

**Example:**
```typescript
// app/api/chat/route.ts
import { chatService } from '@/services/chat-service';
import { requireSession } from '@raweval/auth';

export async function POST(request: Request) {
  const session = await requireSession();
  const body = await request.json();
  
  const message = await chatService.sendMessage(
    session.userId,
    body.message
  );
  
  return Response.json(message);
}
```
