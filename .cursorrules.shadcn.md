# Shadcn UI MCP Server Optimization Rules

## 🎨 Shadcn Component Management

### Using Shadcn MCP Server

**When adding components:**
1. Use MCP server command: "Add shadcn [component-name] component"
2. Server automatically places component in `packages/ui/src/[component].tsx`
3. Import directly: `import { Component } from '@raweval/ui/component'`

**✅ CORRECT Workflow:**
```
1. Ask MCP: "Add shadcn dialog component"
2. Component created in: packages/ui/src/dialog.tsx
3. Import: import { Dialog } from '@raweval/ui/dialog'
4. Use in app: <Dialog>...</Dialog>
```

### Component Structure

**Generated Component Location:**
```
packages/ui/src/
├── button.tsx          # Generated by MCP (DO NOT EDIT)
├── card.tsx            # Generated by MCP (DO NOT EDIT)
├── dialog.tsx          # Generated by MCP (DO NOT EDIT)
└── ...
```

**App-Specific Overrides (if needed):**
```
apps/chat/components/ui/
└── index.ts            # Re-export with customizations
```

### Rules

**✅ DO:**
- Use MCP server to add all shadcn components
- Import directly: `import { Button } from '@raweval/ui/button'`
- Create wrapper components in `features/*/components/` if customization needed
- Use app-specific re-exports in `components/ui/` if needed

**❌ DON'T:**
- Edit components in `packages/ui/src/` directly (they're generated)
- Create barrel exports in `packages/ui`
- Duplicate shadcn components in apps
- Import from `@raweval/ui` (use direct path: `@raweval/ui/button`)

### Customization Strategy

**If you need to customize a shadcn component:**

1. **Option 1: Create wrapper in feature**
```typescript
// features/chat/components/custom-button.tsx
import { Button } from '@raweval/ui/button';
import { cn } from '@raweval/utils';

export function CustomButton({ className, ...props }) {
  return (
    <Button
      className={cn('custom-styles', className)}
      {...props}
    />
  );
}
```

2. **Option 2: Re-export with app-specific defaults**
```typescript
// apps/chat/components/ui/index.ts
export { Button, buttonVariants } from '@raweval/ui/button';
export type { ButtonProps } from '@raweval/ui/button';

// Then use in app
import { Button } from '@/components/ui';
```

### Component Variants

**Using CVA (class-variance-authority):**
```typescript
// Shadcn components already use CVA
import { buttonVariants } from '@raweval/ui/button';
import { cn } from '@raweval/utils';

// Extend variants in your components
const customButtonVariants = cva(buttonVariants, {
  variants: {
    // Add your variants
  }
});
```

### MCP Server Commands

**Common commands:**
- "Add shadcn button component"
- "Add shadcn card component"
- "Add shadcn dialog component"
- "Add shadcn form component"
- "Add shadcn input component"

**The MCP server will:**
1. Download component from shadcn registry
2. Place in `packages/ui/src/[component].tsx`
3. Configure proper imports
4. Set up TypeScript types

### Best Practices

1. **Always use MCP server** to add components (don't copy-paste)
2. **Import directly** from `@raweval/ui/[component]`
3. **Don't edit generated components** - create wrappers instead
4. **Keep components in packages/ui** - shared across all apps
5. **Use feature components** for app-specific customizations

### Troubleshooting

**Issue: Component not found after MCP add**
- Check `packages/ui/src/` for the component
- Run `pnpm install` to link workspace packages
- Verify import path: `@raweval/ui/[component]`

**Issue: Need to customize generated component**
- Don't edit `packages/ui/src/[component].tsx`
- Create wrapper in `features/*/components/` or `components/ui/`
- Use composition or re-export pattern

**Issue: Component styles not working**
- Check Tailwind config in `packages/config/tailwind`
- Verify component uses correct Tailwind classes
- Check if CSS variables are defined
